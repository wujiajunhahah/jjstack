# 反模式清单（jjstack references）

> 三类：措辞、claim、设计。每一条都是真实出现过或差点出现的问题。

---

## 一、措辞反模式

### 中文简历毒药词

| 禁用 | 为什么 | 替代 |
|---|---|---|
| 熟练掌握 / 精通 / 熟悉 | 无验证锚点；出现三次等于没写 | 括号里写实现细节："CoreBluetooth（自研中央端：自定义 GATT、状态恢复、断连降级）" |
| 负责 XX 模块 | 只描述职责范围，不描述结果 | 写做了哪个决策、带来什么变化 |
| 全栈 | 应届生写全栈＝面试官认为是"什么都不精" | 写"纵向打通"的具体链路 |
| 参与 / 协助 | 说不清自己那部分 | 写具体动作 + 范围 |
| 热爱设计 / 有责任心 / 学习能力强 | 谁都能写 | 删 |

### AI 味与空泛词

禁：显著提升、赋能、打造闭环、全链路打通、深入洞察、多维度、降本增效、助力、场景化落地

禁：em 破折号（—）连接关键信息。ATS 解析里它排第三大损坏原因（19%）。

### 口吻

- 不写"你可以考虑 A、B、C" → 挑一个做，报结果
- 不写开场套话（"很好的问题""让我帮你…"）
- 不写没有动作的总结段
- 短段落，一段一个意思
- 技术名词保留英文原词（BLE / Core ML / Harness / PRD / SSE）

## 二、Claim 反模式

### 无证据的数字

| 反模式 | 规范做法 |
|---|---|
| 「大幅提升」 | 给数字 + 测量方式 + 样本 + 对照 |
| 用"单次推理延迟"当用户体验延迟 | 测端到端，并写清测的是什么 |
| N=1 写成"实验表明有效" | 「N=1 形成性配对实验，方向性证据，不能替代大样本结论」 |
| 把模型准确率当成产品效果 | 「（准确率数值见本机 references/facts.md） 是五类手势分类准确率，不是工作状态判断准确率」 |
| 只给总分不给逐项 | 逐类给 precision/recall，否则宽泛类目会拉低并误砍可用能力 |

### 冒领与归属

- 用他人开源成果冒充自己设计 → 必须写清"上游是谁 + 我做了什么"
- 团队成果写成个人完成 → 写团队人数 + 本人具体范围
- 官方署名与自述不一致时，不单方面升级表述

### 只写成功路径

- 未完成的闭环必须写进 README / 文档
- 引用内部素材里"尚未实现"的设想当成果（素材文件里若已标"不得写成当前成果"，就不写）

### 跨材料不一致

同一件事在简历 / BOSS / 网站 / README / 答辩里必须同一口径。定稿前做对照。

## 三、设计反模式

| 反模式 | 为什么不行 | 规范做法 |
|---|---|---|
| 把通知当交互 | 通知本身就是打断 | 反馈放进环境（光 / 动作 / 呼吸律动） |
| 弹窗 + 振动解决一切 | 与"不抢占注意力"前提冲突 | 分级介入，默认停在静默记录 |
| 动效只为好看 | 无对应语义，增加认知成本 | 每个动效说得出"它表达什么" |
| 通用阈值套所有人 | 个体差异大，误报率高 | 个体基线校准 |
| 检测到就打断 | 短暂波动不是风险信号 | 持续时间阈值（如 >5 分钟）+ 冷却期 |
| 实时数字仪表盘 | 制造焦虑，与低打扰冲突 | 专注模式不显示细节，只给"继续/建议暂停" |
| 全自动化不可中断 | 用户失去控制权 | 保留人工确认、可取消、失败降级、审计 |
| Mock 当已实现 | 后面要推翻重写 | 名字里带 `Mock`，README 注明 |

## 四、工作方式反模式

| 反模式 | 规范做法 |
|---|---|
| 命题里的解决方案当成问题 | 先写「不是 A，而是 B」 |
| 模拟器跑通就宣布完成 | 真机端到端至少跑通一次 |
| 协议没定就写多个消费端 | 先写状态帧 schema |
| 异常路径放到"第二版" | 与主链路同等优先级 |
| 每推进一步就汇报 | 先记录，有证据且不打断会造成损失时才打断 |
| 用"需要你确认"包裹自己的不确定 | 给建议 + 理由，让人做决定而不是替他做 |
| 海投同一份简历 | 一岗一版，换的是排序不是事实 |
| 堆砌 JD 关键词 | 用可核实的数字承担说服力 |

## 五、一句话判据

写完任何对外内容，问三句：

1. **这句话被追问三层，我答得上吗？**
2. **去掉它，读者对我的判断会变得更不确定吗？**（不会 → 多余）
3. **它有没有把"我做到的"和"我希望的"混在一起？**
