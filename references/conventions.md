# 技术惯例（jjstack references）

> 选型、架构、目录、命名。不是教条，是已经跑通过的做法。偏离可以，但要说出理由。

---

## 架构：协议先行

任何多端系统先写**状态帧 schema**，再写消费端。

```
[输入源] → [判断层] → [状态协议帧] → [消费端 A]
                                   → [消费端 B]
```

状态帧至少包含：

| 字段 | 作用 |
|---|---|
| `timestamp` | 时序对齐 |
| `source` | 来源模块（用于多源融合与问题定位） |
| `quality` / `confidence` | 质量权重；低于阈值时消费端应忽略 |
| `state` | 状态值本身 |
| `basis` | 这个判断基于什么证据（用于"可解释") |

**为什么**：解耦状态生产与设备执行。设备成为状态的持续消费者，而不是"收到命令才动"的外设。加新端时不用改动判断层。

参考实现：一个可穿戴状态感知项目 的 `harness-protocol`（`状态帧 schema` + WS 广播规范）。

## 分层

| 层 | 职责 | 不该做什么 |
|---|---|---|
| 感知层 | 采集原始信号、做基础清洗 | 不做业务判断 |
| 判断层 | 多源融合、个体校准、输出状态 | 不关心谁消费 |
| 协议层 | 定义状态帧与传输 | 不含业务逻辑 |
| 消费端 | 决定怎么表达 | 不重复判断 |

## iOS

- **SwiftUI 优先**，除非有明确理由用 UIKit
- 硬件直连走 `CoreBluetooth`：自研中央端要处理**状态恢复、断连重连、降级**
- 端侧推理走 `Core ML`（`.mlpackage`）；模型契约（输入维度、类别、特征顺序）写进配置文件，不要散在代码里
- 持久化用 `SwiftData`：迁移计划 + 内存降级兜底
- 系统级呈现：`WidgetKit`（TimelineProvider）+ `Live Activity`（灵动岛）
- 视觉理解用 `Vision`：OCR 走 `VNRecognizeTextRequest`，实时流注意节流
- 隐私：默认本地，需要上传的字段写进隐私说明

## 硬件 / BLE

- BLE 与串口能力**不一样**，要分别测：通道数、采样率、丢包率都可能不同
- 二进制帧协议要写下来（字段、字节序、有符号/无符号），并有 `tools/serial_probe` 这类探测脚本
- 异常路径与主链路同等优先级：**断连、脱落、低电量、超时、权限拒绝**
- 固件与 App 的字段定义**共用一份**（避免两边各写一遍）

## 端侧模型

- 训练暴露离线评估：数据集、划分方式（如 Leave-One-Group-Out）、指标（准确率 + F1）
- 导出格式：`.onnx` / `.mlpackage` / `.pkl`，权重走 Releases，不进仓库
- 部署后测**端到端延迟**，不要拿"单次推理"当用户体验延迟
- 模型不可用时要有降级路径（回规则引擎 / 回静默记录）

## 后端

- `FastAPI` + `REST`；需要推流用 `SSE`（简单、可断线重连）
- 事件契约与 iOS 端共用同一份定义（同一事件两种语言各写一遍必出岔子）
- 分层路由：`auth / sessions / models / devices / feedback`

## 前端 / 网站

- 静态优先；需要交互再上框架
- 落地页要有：一句话定位、可点的主要入口（App Store / GitHub）、隐私说明
- ⚠️ 链接失效会直接损害可信度，发布后周期检查

## 交付形态怎么选

| 形态 | 判据 |
|---|---|
| App Store | 单端可独立使用、有隐私说明、崩溃率可控 |
| TestFlight | 还在迭代、需要多人反馈 |
| 实机演示 | 硬件/机器人；必须能被别人复现步骤 |
| 开源 | 引擎/协议/算法；README 写清能跑什么、不能跑什么、怎么装 |

## 目录与命名

```
project/
├── README.md            # 一句话、能跑什么、不能跑什么、怎么装
├── docs/                # 架构、协议、排障
├── src/ 或 ios/ web/    # 按端分
├── tools/               # 探测、诊断脚本
├── scripts/             # 训练、导出、部署
└── tests/
```

- 协议文件：`*-protocol.md` / `*_protocol.*`
- 探测脚本：`tools/*_probe.py`
- 模型配置：`model_meta.json`（维度、类别、特征顺序、限制）
- 报告：`*Report/`（中期检查、验证记录）
- 命名避免版本号后缀（`final`、`v2`），版本交给 git

## README 必备四段

1. 一句话（它是什么）
2. 能跑什么 / 怎么装
3. **不包含什么 / 还没做到什么**
4. 关键设计取舍（为什么这样，不那样）

第 3 段是硬要求。没有它，别人会按最理想的理解去期待。
