# 怎么给这个套件写新技能

## 先问三个问题

1. **它和现有技能是同一件事吗？** 是就改进现有的，不要加新的。
2. **它的判据能写成条件吗？** "输出要好"不是判据；"能回答怎么测、样本多少、对照组是什么"才是。
3. **它的反模式说得清吗？** 写不出至少三条，说明你还没见过足够多的失败案例。

---

## 一个技能的最小结构

```markdown
---
name: jj-<name>
description: <一句话，包含触发条件；20–400 字>
---

{{PREAMBLE}}

# <技能名>

## 何时用
<什么情况下该走这条流程；什么情况下不该>

## 工作流
<编号步骤，每步一个动作、一个产出>

## 反模式
<至少三条，来自真实见过的失败>

## 自检
- [ ] <可勾选的判据>
```

四条缺一不可。没有"何时用"技能会被乱调用；没有"自检"没法验收。

---

## 写法约定

**判据要能被追问。**
- ❌ "确保质量足够高"
- ✅ "每条对外陈述配一句它能证明到哪一步"

**步骤要能被执行。**
- ❌ "深入分析需求"
- ✅ "写一句「不是 A，而是 B」；写不出来就停下来"

**反模式要有具体形态。**
- ❌ "避免常见错误"
- ✅ "把命题里的解决方案当成问题本身"

**用例子代替形容词。**
每个抽象判断后面跟一个具体形状，哪怕是把真实案例脱敏后的形状。

---

## 加进去的流程

```bash
mkdir -p jj-<name>/agents
# 1. 写 jj-<name>/SKILL.tmpl（用上面的最小结构）
printf 'policy:\n  allow_implicit_invocation: false\n' > jj-<name>/agents/openai.yaml
# 2. 在 SKILL.tmpl 的路由表加一行
# 3. 生成 + 验证
python3 scripts/gen-skills.py
python3 scripts/validate.py
```

验证器会检查：name 与目录一致、description 长度、路由双向一致、体积上限。

---

## description 怎么写（决定会不会被调用）

包含三件事：**做什么 + 什么时候用 + 触发词**。

```yaml
description: 口径审查。把简历、README、答辩、官网、邮件里所有对外陈述逐条抽取、分级、整改。
  当要检查某个数字或说法能不能说、项目上线前自查、投递材料定稿前时使用。属于 jjstack 套件。
```

反面：`description: 帮助提升工作质量。` —— 没有任何路由信息。

---

## 体积

单文件上限见 `AGENTS.md`。**超了就拆分，不要放宽阈值。**

拆分方向：
- 长清单 → 移到 `references/`
- 长例子 → 移到 `examples/`
- 两个独立流程 → 拆成两个技能

---

## 别忘了 register

新技能必须在 `SKILL.tmpl`（路由器）的路由表里出现，否则 `validate.py` 会报"存在但未被路由"。
